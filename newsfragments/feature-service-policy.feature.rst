Added an explicit service admission policy (``keyring.policy``) and policy-aware entry points (``keyring.service``) that separate backend *availability* from *security capability*. Resident/daemon processes can now forbid interactive unlock prompts, reject backends with unknown capability, and fail closed (instead of falling back to the null/fail backend) when no compliant backend is available. Automatic selection, explicitly named backends, and the chainer all run a preflight check before any credential is read; diagnostics explain each decision without exposing secret material.
